# VPS Guard

面向 Linux VPS 的中文交互式服务器保护工具，独立运行，无需面板或数据库。

- **防火墙管理**：安装、启动、关闭及重启/重载，关闭时保留已保存的端口规则。
- **TCP 端口管理**：查看、添加、修改及删除本工具规则，保护当前 SSH 端口。
- **SSH 端口修改**：检查端口占用、自动放行防火墙、验证监听，并同步本工具 Fail2ban 防护端口。
- **Fail2ban 防护**：安装启用、参数设置、状态与封禁查询、解封、持久白名单及日志。

## 安装与更新

在服务器的 **SSH 交互终端** 执行：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/wx11xz111/vps-guard/main/bootstrap.sh)
```

安装器下载固定提交的脚本并校验 SHA256，安装至 `/usr/local/lib/vpsmanager/server-guard`，随后打开中文菜单。安装器本身不启用防火墙或修改 SSH 配置；菜单中的变更会另行预览并确认。

安装后可在任意目录运行：

```bash
vps-guard
```

**更新已有安装**：重新执行上方安装命令。普通用户启动时通过 sudo 提权，并保留当前 SSH 会话信息。

支持 Debian 11+、Ubuntu 22.04+、Rocky Linux / AlmaLinux / RHEL 8+、CentOS Stream 9+。运行需要 systemd、Bash 4.4+、curl、GNU 工具、flock、OpenSSH、ss，以及 root 或 sudo 权限。不支持 CentOS 7。

## 菜单速查

主菜单按功能连续编号为 **1–18**。本版已重新编号，请按当前显示选择，旧版编号不再沿用；命令行动作名称保持不变。

| 功能 | 菜单编号与操作 |
| --- | --- |
| 防火墙安装与启停 | **1** 安装并启用 · **2** 启动 · **3** 重启/重载 · **4** 关闭并保留规则 |
| 本工具 TCP 端口 | **5** 查看 · **6** 添加 · **7** 修改 · **8** 删除 |
| SSH 端口 | **9** 修改端口并同步防护，保留原端口 |
| Fail2ban 快捷操作 | **10** 安装并启用 · **11** 停用本工具 SSH 防护 · **12** 配置参数 |
| Fail2ban 综合管理 | **13** 状态、参数、解封、白名单、日志及服务重启 |
| 状态与维护 | **14** 查看状态 · **15** 查看完整防火墙规则 · **16** 查看备份和执行结果 |
| 清空规则 | **17** 清空本工具端口 · **18** 清空受支持的整机规则 |
| 退出 | **0** 退出；子菜单中返回上级 |

菜单 15 可查看本工具之外的规则，包括 UDP 和 IPv6 规则；菜单 6/7/8 管理本工具的普通 TCP 端口，不允许修改或删除 SSH 保护端口。

## 常用流程

### 首次配置

1. 尚未安装防火墙时，选择 **1**。Debian/Ubuntu 安装 UFW，RHEL 家族安装 firewalld；启用前先准备已识别 SSH 端口的放行规则。
2. 选择 **6** 放行业务所需的 TCP 端口，用 **5** 查看本工具端口或 **15** 查看完整规则。
3. 选择 **10** 安装并启用 SSH 防爆破；需要调整参数、查看封禁或解封时，进入 **13**。

已有防火墙时沿用当前管理器。支持 UFW、firewalld、iptables 和 nftables；多管理器冲突、复杂规则及持久化要求见[操作手册](MANUAL.md#防火墙与-ssh-范围)。云安全组中的端口需自行放行。

### 关闭后重新启动防火墙

选择 **4** 关闭过滤并禁用开机启动，保留已保存规则；选择 **2** 重新启动，工具先补齐 SSH 放行，再加载已保存规则。

选择 **3** 重新加载规则。UFW/firewalld 采用重载；firewalld 会读取永久配置，未保存的临时业务规则不会保留。清空规则使用独立的 **17/18** 入口。

### 修改 SSH 端口

选择 **9** 并输入新的 TCP 端口，执行流程为：

```text
检查占用 → 校验候选配置 → 准备防火墙及 SELinux 放行
         → 重载 SSH 并验证新端口监听 → 同步本工具 Fail2ban 防护
```

原 SSH 端口继续保留。请先在云安全组放行新端口，修改后保留当前连接，并用新连接验证访问；验证不需要回到工具执行二次确认。

检测到 socket 激活时，预览会说明切换到 SSH 服务监听；仅在服务未被管理员屏蔽且具备保留会话的设置时执行。Fail2ban 已停止或本工具防护已停用时，只同步端口配置，保持原启停状态。其他工具配置的 SSH jail 需自行检查。

### 管理 Fail2ban 防护

首次启用默认使用：

| 参数 | 默认值 |
| --- | --- |
| 最大失败次数 | 5 次 |
| 统计窗口 | 600 秒 |
| 封禁时长 | 3600 秒 |

菜单 **12** 可修改参数，回车保留当前值；再次启用或同步 SSH 端口会保留已有参数和白名单。菜单 **13** 进入防护管理子菜单：**1** 状态及封禁列表、**2** 安装启用、**3** 参数、**4** 停用本工具防护、**5** 重启服务、**6** 解封 IP、**7** 添加白名单、**8** 日志、**0** 返回。子菜单编号与主菜单独立。

缺少 Fail2ban 时，确认后通过系统软件源安装服务端及 systemd 日志依赖；无需先启动防火墙。RHEL 家族需要可提供相关软件包的仓库，工具不自动添加 EPEL。仅预览或取消不会安装软件。

停用、解封和白名单仅针对本工具的 `server-guard-sshd` jail；**重启 Fail2ban 服务会涉及全部 jail**，执行前会明确提示。添加白名单会持久保存，并在本工具防护运行时解除该地址的封禁；单独解封不会加入白名单。

## 操作提示与备份

变更前统一使用 `[y/N]`：`Y/y` 执行，`N/n` 或回车取消。成功后立即生效，可在同一连接连续操作，无执行后的二次确认或自动回退。部分步骤失败时，已完成的变更可能保留，工具会报告失败结果。

端口、SSH、Fail2ban 及防火墙启停变更会保存备份，可通过 **16** 查看编号、执行结果和校验状态。首次安装防火墙的菜单 1 不创建编号备份。备份供检查及手工处理使用，工具没有恢复入口；位置和范围见[备份说明](MANUAL.md#备份与结果)。

升级后首次进入菜单或执行变更时，会停用旧版确认/回退任务并归档旧待确认记录，保留当前配置和原备份。恢复、确认和回退功能已取消。

终端以颜色区分内容：青蓝色为标题/信息，绿色为启用/成功，黄色为提醒/确认，红色为错误/删除/清空，紫色为输入。重定向或管道输出使用纯文本，也可手动关闭颜色：

```bash
NO_COLOR=1 vps-guard
```

完整命令行用法、依赖和支持边界见[操作手册](MANUAL.md)。

## 验证范围

已完成 Bash 语法检查、Windows Git Bash 下的隔离函数级命令适配器回归，以及安装器下载和 SHA256 校验。另有 Ubuntu 24.04 公网环境的历史 SSH 登录、只读查询和菜单验证记录。

当前流程的完整 Linux 回归、真实防火墙变更、SSH/socket 切换、系统重启及 SELinux 内核行为仍需实机验收，隔离检查不代表这些场景已经通过。
